11/**
12 * @brief The Finally node ticks its first child ("main") and then ticks its
13 * second child ("cleanup"), like try/finally.
14 *
15 * - Cleanup runs after main returns SUCCESS or FAILURE. If main returns SKIPPED on
16 * its first tick it did nothing, so cleanup is not run and the node returns
17 * SKIPPED. If main is skipped after it returned RUNNING, for example by _while,
18 * cleanup runs and the node returns SKIPPED.
19 * - If main throws (any type), main is halted, cleanup runs, and then the
20 * exception is rethrown.
21 * - The node returns main's status, or FAILURE if cleanup fails.
22 * - If this node is halted while main or cleanup is RUNNING, main is halted and
23 * cleanup gets one tick, like TryCatch with catch_on_halt="true". A cleanup that
24 * needs several ticks is cut short by the final halt of its subtree. That tick
25 * runs inside halt(), on the calling thread and under any lock the caller holds,
26 * so a cleanup action that blocks also blocks the caller.
27 * - The single tick suits synchronous cleanup. An asynchronous cleanup child (e.g. a
28 * StatefulActionNode) gets onStart() and then onHalted() right away. Use
29 * "halt_timeout_msec" for asynchronous cleanup on halt.
30 * - To let a multi-step cleanup finish, set "halt_timeout_msec" above 10 (the tick
31 * period). Then halt() ticks cleanup once, and again every 10 ms until it finishes,
32 * fails or throws, or the timeout runs out, in which case cleanup is halted
33 * unfinished. No tick starts after the timeout, and a tick that blocks is not cut
34 * short. With 10 or less, cleanup gets a single tick.
35 * - That loop BLOCKS the halting parent, e.g. a ReactiveSequence, for up to
36 * halt_timeout_msec, and nothing else in the tree is ticked meanwhile. An
37 * enclosing Timeout that holds its mutex during the child's tick is delayed by up
38 * to the same amount, and nested Finally nodes with the option set add up their
39 * timeouts. Keep the value short.
40 * - The loop runs only when halt() is called from the thread that last ticked this
41 * node. A halt from another thread, such as a Timeout decorator's timer or a
42 * service callback calling Tree::haltTree(), gives cleanup the single tick and
43 * prints a note to stderr. A Finally nested inside that halt also gets a single
44 * tick. If halt() is called while another halt() of this node is still running,
45 * it returns at once and leaves the cleanup to the first one. halt() is not
46 * synchronized with a concurrent tick().
47 * - An exception thrown by cleanup in tick() halts cleanup, leaves the node
48 * IDLE and propagates. It replaces main's status, or main's exception,
49 * which is dropped. The next tick starts with main.
50 * - halt() never throws, because it also runs from ~Tree(). It prints to
51 * stderr when cleanup throws, fails or times out, and when halting a child
52 * throws. A pending exception from main is printed and dropped by a halt.
53 *
54 * Requires exactly 2 children, checked when the XML is loaded and on tick.
55 */
